## 1. The Codex handoff

**Nothing Codex wrote is on GitHub.** No commit in either repo, on any branch,
comes from Codex. Every commit is Claude's, the owner's, or the 09-28 import of
the host's working copy (`af0c32e`, "Import Alpha from E:\AlphaData").

The owner identifies the handoff as
`software/backend/adaptive_system_context.py` in the Alpha app. That file came
in with the 09-28 import, so git cannot say who wrote it. It is code, not a
document. What it is and how it holds up:

| | |
|---|---|
| **What it does** | Builds a "system map" of Alpha, holding structure only and no source bodies: the 16 deck ids, the 23 hub ids, the app profiles, and the `@app.<verb>` routes and public top-level names in `main.py`, with a SHA-256 receipt per source file. `prompt_summary()` puts the routes and apps relevant to a chat turn into the prompt, capped at 5,500 characters, with a "not consciousness, liveness, or execution proof" boundary line. |
| **Where it is wired** | `main.py`: imported at the top, injected into every chat prompt (`_build_alpha_prompt`), refreshed off the event loop 20 s after startup and saved as `alpha_system_map_latest`, and served at `GET /alpha/system-map` (signed-in users). |
| **Tests** | `tests/test_adaptive_system_context.py`: **2/2 pass**. |
| **Cost** | Cold build 0.46 s; cached (mtime+size key) 0.2 ms. The chat path stays fast because the startup refresh warms the cache first. |
| **Prompt safety** | Routes whose path mentions password, secret, token, key or credential are left out. On four sample prompts, the summary stayed well under its cap, remained valid JSON and kept the boundary line. |
| **Gap: it sees half of Alpha** | It parses only `main.py`. It indexes **445** routes, but the `api/*.py` routers declare another **627** route decorators that are invisible to it. Among them: the host terminal, monetization, cortex/coordination status and all music routes. Asked about those, Alpha's chat is grounded in a map that says they do not exist. Extending it to `@router.*` in `api/` (honouring the `main.py`-wins dedupe) is the obvious follow-up. |
| **Minor** | `missing_sources` suggests missing files are tolerated, but only `hubRegistry.js` actually is. A missing `main.py`, `deckConfig.js` or `Hubs.jsx` raises an error. Both callers catch it (chat logs a warning; startup marks `system_map_refresh: degraded`), so chat keeps working. |

**Verdict:** safe, bounded and correctly wired. Keep it. Its coverage is the only real problem.

The handoff *documents* addressed to Codex (`CODEX_MESSAGE_2026-09-30.md`,
`HANDOFF_LAPTOP41_2026-09-30.md` §4) now have no reader. Their open questions

**New in the code merged since 09-30:**

- **Medium:** request validation errors echo the rejected input. For example, an
  over-long payment-provider key comes back in the 422 body, and a malformed
  login body echoes its password field. The fix is a validation handler that
  strips `input`. This is owner-only for the payment route; the login echo goes
  back to whoever sent it.
- **Medium:** the chat failure messages (#15) misdiagnose two common faults.
  - A stopped backend arrives as Vite's empty 502 and is shown as "backend returned an error".
  - Any error containing "token", such as a context-length or tokenizer error, is shown as "sign-in rejected".
- **Low:** the edge-health report hard-codes backend port 8001, so a port-8000
  deployment reads as "backend down". Any signed-in user can trigger its
  5 outbound probes and a disk write per call, uncached.
- **Low:** cloudflared log lines flow into the chat prompt through the edge
  summary.
- **Low:** the unauthenticated readiness and credits endpoints reveal whether a
  live payment account is connected. A transient DNS failure on re-verify is
  treated as a revoked key.

| Any `tasks:read` key sees every payload | **Open** | Includes the panel's Wi-Fi password and tunnel key, and Codex prompts. Kept for 24 h. |
| Legacy and bootstrap tokens stay admin after users exist | **Open** | Logs a warning only |

**New:**

1. **`scripts/move-coordinator-here.mjs` breaks every re-run after a failure past the invite.**
   - The invite persists `data/auth.json` before the password is prompted. A short or mismatched password leaves a store with 0 users.
   - The next run keeps that store, writes `.env` without a bootstrap token, and the coordinator refuses to start.
   - Workaround: delete `data/auth.json` before re-running.
2. **The same script's `die()` exits inside `try/finally`, so the temporary coordinator stays up.** It keeps listening with its bootstrap admin token live. The next run then misreports "a coordinator already answers".
3. **`codex.exec` lease equals its timeout** (both 600 s). The handler's own timeout never fires, and a slow prompt is retried 3 times, which is up to about 30 minutes of Codex usage. `maxAttempts: 1` would suit a non-idempotent call.
4. **`alpha.music.audio` slices (about 700 KB each) are kept in host memory** for 24 h, up to 1,000. That can reach hundreds of MB and undoes part of #51.
5. Smaller issues:
   - `codex.exec` on Windows can pick `codex.cmd` (refused) from an earlier PATH entry over a `codex.exe` later on PATH;
   - a failed bridge download leaves `.part` files that are never pruned.

- **Step 8 publishes the music bridge to the internet.** `preview.proxy` reuses `server.proxy`, and cloudflared serves the preview. The bridge has no auth (§5). Use Alpha #16, which adds a local-only guard, instead of the one-line proxy entry.

- **Step 3 ("append to `.env.agent`") is silently overridden** while `ALPHA_EXTRA_HANDLERS` is still set in Laptop41's machine environment.

- **Step 9's `ALPHA_MUSIC_DRY_RUN=1` belongs in the agent's environment.** Set only in the bridge's shell, the first Generate downloads the real model.
